# Data inventory (Phase F1)

Every field this app stores, derived directly from `packages/db/src/schema/*.ts` (the source of
truth). Written to support a DPIA. "Retention" references the env-configurable windows documented in
`docs/security.md` — all marked **[LEGAL REVIEW REQUIRED]** there, not repeated per-row here.

## health schema

Every table here is scoped by Postgres row-level security to `current_setting('app.user_id')` — see
`packages/db/src/client.ts`'s `withUser`. The one exception is `assessments`, which also has a second,
narrowly-scoped RLS policy for de-identified staff review (see below).

| Table           | Fields                                                                                                                                                                                                                                  | Purpose                                            | Retention                                                                                                                     | Who can access                                                                                                                                                                                                                                                                     |
| --------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `cycles`        | `id`, `user_id`, `start_date`, `end_date`, `predicted`, `created_at`, `updated_at`                                                                                                                                                      | Derived period-cycle ranges (from period-day logs) | Deleted on account deletion (cascade)                                                                                         | Self only                                                                                                                                                                                                                                                                          |
| `symptom_logs`  | `id`, `user_id`, `log_date`, `period_day`, `bleeding_level`, `pain_score`, `pain_locations`, `symptoms` (jsonb), `impact` (jsonb), `red_flags` (jsonb), `notes_enc` (AES-256-GCM), `client_id`, `synced_at`, `created_at`, `updated_at` | Daily symptom tracking                             | Deleted on account deletion (cascade)                                                                                         | Self only                                                                                                                                                                                                                                                                          |
| `assessments`   | `id`, `user_id`, `ruleset_version`, `outcome`, `reasons` (jsonb), `fired_rule_codes`, `features` (jsonb), `created_at`                                                                                                                  | Immutable triage recommendation record             | Deleted on account deletion (cascade)                                                                                         | Self only, **plus** clinician quality review (`listCaseSamples`, `withStaffReview`) which reads `age_band`/`county`/`outcome`/`fired_rule_codes`/`features`/week-truncated date **only** — never user id, phone, or free-text notes, and never joined back to an identifiable user |
| `chat_sessions` | `id`, `user_id`, `created_at`, `updated_at`                                                                                                                                                                                             | Groups a conversation's messages                   | Deleted when its messages age out or on account deletion                                                                      | Self only                                                                                                                                                                                                                                                                          |
| `chat_messages` | `id`, `session_id`, `user_id`, `role`, `content_enc` (AES-256-GCM), `safety_flags` (jsonb), `sources`, `created_at`                                                                                                                     | Assistant conversation history                     | `CHAT_RETENTION_DAYS` (default 90) via the nightly retention job, or sooner on account deletion                               | Self only                                                                                                                                                                                                                                                                          |
| `summaries`     | `id`, `user_id`, `period`, `pdf_key`, `share_token_hash` (SHA-256 of the raw token, which is never stored), `expires_at`, `revoked_at`, `view_count`, `created_at`                                                                      | Clinician-summary PDF + share link metadata        | `SHARE_LINK_RETENTION_DAYS` (default 7) after expiry/revocation via the retention job (deletes the DB row and the PDF object) | Self (own summaries), **plus** anyone holding the raw, unguessable share-link token (`/s/[token]`, rate-limited by IP) — by design, since that's the clinician-sharing feature; revoking deletes access immediately                                                                |
| `quiz_attempts` | `id`, `user_id`, `prompt_kind` (`onboarding`/`day30`), `score`, `total_questions`, `created_at`                                                                                                                                         | Knowledge-check scores                             | Deleted on account deletion (cascade)                                                                                         | Self only; aggregate score-change bands (not raw scores) feed `analytics.events`                                                                                                                                                                                                   |

## analytics schema

Never joined to identity; `pseudo_id` is a keyed hash with no reversal path back to a user.

| Table    | Fields                                                                                                                                                                        | Purpose                                   | Retention                                                                                                                                                                   | Who can access                                                                                                                                                                                                                                                                                              |
| -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `events` | `id`, `pseudo_id` (keyed hash, `ANALYTICS_KEY`), `event_type`, `county`, `age_band`, `locale`, `props` (jsonb, event-specific, never raw symptom/chat content), `occurred_at` | Event-sourced impact-dashboard aggregates | Not currently covered by the retention job (event-sourced, pseudonymous, and the materialized views already small-cell-suppress — revisit if counsel wants an explicit cap) | Write: `analytics_writer` role (INSERT only, no SELECT — see `packages/db/drizzle/0009`). Read: only via the pre-aggregated, suppressed materialized views (`mv_*`), by `programme_admin`/`system_admin` on the impact dashboard — the raw `events` table itself is never queried by any staff-facing route |

## Fields never stored

Per CLAUDE.md: raw location (used only for the specific facility-search request, never persisted or
sent to analytics), unvalidated diagnostic probabilities/confidence scores, and real email addresses
(the `email` column always holds a generated non-routable placeholder).
