# MweziCare AI

AI-powered menstrual health companion for girls and young women in Kenya. See
[CLAUDE.md](CLAUDE.md) for the product summary, stack and non-negotiable
safety/privacy rules that govern every change in this repo.

## Docs

- [Technical Architecture](docs/MweziCare_AI_Technical_Architecture.docx)
- [UNICEF Femtech Proposal](docs/MweziCare_AI_UNICEF_Femtech_Proposal.pdf)

## Prerequisites

- Node.js 20+
- pnpm (`npm install -g pnpm` if you don't have it — Node's bundled
  `corepack` was removed in recent Node releases, so install pnpm directly)
- Docker Desktop (for local Postgres)

## Getting started

```bash
pnpm install
cp .env.example .env   # fill in real values; dev defaults work for most
pnpm db:up              # starts Postgres 16 + PostGIS + pgvector + pgcrypto
pnpm dev                # http://localhost:3000 -> redirects to /en
```

Visit `/en` or `/sw` to see the app in each locale, with the bottom
navigation (Track · Insights · Ask · Care · Me).

## Workspace layout

```
mwezicare/
├─ apps/web/              # Next.js app (PWA + API + admin)
├─ packages/
│  ├─ db/                 # Drizzle schema, migrations, seed (task A2)
│  ├─ rules-engine/       # deterministic triage rule DSL + evaluator
│  ├─ triage/             # feature extraction over cycles + symptoms
│  ├─ assistant/          # RAG retrieval, prompts, safety filters
│  ├─ facilities/         # KMHFL importer, geo search
│  ├─ validation/         # shared Zod schemas (incl. env validation)
│  ├─ ui/                 # shared components (shadcn/ui-style primitives)
│  ├─ tsconfig/           # shared tsconfig presets
│  └─ eslint-config/      # shared flat ESLint config
└─ content/                # clinician-approved articles (EN/SW, Markdown)
```

`packages/ui` holds hand-built shadcn/ui-style primitives (`cn` util, `cva`

- Radix `Slot`-based `Button`, a presentational `BottomNav`) rather than
  files generated by the `shadcn` CLI, so the scaffold has no registry
  dependency. `apps/web/components.json` is pre-configured so `npx shadcn add
<component>` drops new primitives straight into `packages/ui/src`.

## Common commands

| Command                       | What it does                                      |
| ----------------------------- | ------------------------------------------------- |
| `pnpm dev`                    | Start the Next.js dev server                      |
| `pnpm db:up` / `pnpm db:down` | Start/stop local Postgres via Docker Compose      |
| `pnpm db:migrate`             | Run Drizzle migrations (task A2)                  |
| `pnpm db:seed`                | Load synthetic seed data (task A2)                |
| `pnpm lint`                   | Lint every package (Turborepo)                    |
| `pnpm typecheck`              | Typecheck every package                           |
| `pnpm test`                   | Run unit tests (Vitest) in every package          |
| `pnpm test:e2e`               | Run Playwright end-to-end tests (mobile viewport) |
| `pnpm build`                  | Production build                                  |
| `pnpm format`                 | Format the repo with Prettier                     |

A pre-commit hook (Husky + lint-staged) runs ESLint and Prettier on staged
files automatically.

## Environment variables

See [`.env.example`](.env.example) for the full list. They're validated at
server startup with Zod (`packages/validation/src/env.ts`, wired up via
`apps/web/instrumentation.ts`) — a missing or malformed variable fails fast
with a readable error instead of surfacing later as a runtime bug.

## Internationalisation

English (`en`) and Kiswahili (`sw`) via `next-intl`, with the locale always
in the URL (`/en/...`, `/sw/...`). Message files live in
`apps/web/messages/`. Every user-facing string must exist in both files —
see the Definition of Done in [CLAUDE.md](CLAUDE.md).
